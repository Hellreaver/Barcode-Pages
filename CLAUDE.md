# Barcode-Pages

Android app (Kotlin, Jetpack Compose) that redraws store tote labels as Code 128 barcodes after a failed dispense. See README.md for how it works.

- Push straight to `main`; the owner does not use pull requests. Each push runs `.github/workflows/release.yml`, which tests, builds and publishes the next release. Versions have two digits after the dot and step by one per published release: 1.15, 1.16 … 1.19, 1.20 … 1.99, 2.00 (the workflow counts from the newest `vX.YY` tag, so failed builds leave no gap). The versionCode is the same number without the dot (1.15 is 115); the older 1.0.1 to 1.0.14 builds used codes 1 to 14.
- Each release's notes are the subject lines of the commits since the previous release. Write commit subjects for the person installing the app ("Fix Samsung keyboard dropping the first typed letter"), not for developers, and keep one user-visible change per commit.
- Name every release APK `Barcode-Pages-<version>.apk` (for example `Barcode-Pages-1.15.apk`) so downloads are identifiable on the phone. Keep the version in the file name in any new build or release step.
- The signing key lives only in the `SIGNING_KEYSTORE` and `SIGNING_PASSWORD` Actions secrets. Never commit a keystore or password; the repository may go public.
- Codes are shown and encoded in the case their store label uses, set by `labelCase()` in `ToteStore.kt`: trip labels (`TL` prefix) keep a lowercase trip id (`TL0a1b-2`), everything else is capitals (`Z13334`). Code 128 keeps case, so the barcode has to match the printed label. The text field keeps exactly what the keyboard typed and changes case only on screen (`LabelCaseTransformation`) and in `Tote.label`, one character at a time so the length never changes. Never rewrite the field value while typing, and never change a field's `KeyboardOptions` while it has focus: either one restarts the keyboard connection, and Samsung's keyboard (Galaxy Note9) then drops the first letter.
- Store tote labels: the barcode is plain Code 128 (`]C0`, no FNC1) holding only the code printed bottom right, such as `Z13334` or `Y98760`, one capital letter and five digits so far. Trip labels hold `TL<trip id>-<n>`, printed just above their bars; known so far: `TL0a1b-1`, `TL0a1b-2`, `TL4821-1` (four-character trip ids, lowercase letters). The owner expects it may grow a sixth digit or use other letters, so use that format for examples and defaults but never block or warn on a code that doesn't fit it. Keep customer names and the store chain's name out of the repo; the repository may be public.
- Target phones: Pixel 8a and Pixel 8 Pro. Screenshot tests render at 411 x 914 dp and 448 x 997 dp.
- Colors and type follow the Lemon-Checklists house style (`Theme.kt`).
- Run `./gradlew testDebugUnitTest` before pushing. Add `-Proborazzi.test.record=true` to write screen PNGs to `app/build/screenshots/`, and decode the barcodes in them to confirm they scan.
